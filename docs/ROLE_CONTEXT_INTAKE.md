# Role Context Evidence Interview

Use this private interview before adding a durable target family or an application context that changes claims, gaps, disclosure, or location. Skip it when an application adds only company metadata and changes none of those decisions.

The purpose is to separate four questions:

1. Can Sam perform the work?
2. Is the supporting evidence direct, transferable, missing, or not yet verified?
3. Can a recruiter or hiring manager verify it from the current artifact?
4. Should the evidence be public, reference-check only, or retained as a named gap?

## Privacy boundary

Run the interview in a private pursuit workspace or an ignored repository handoff. Keep raw answers, private references, contact paths, precise contact details, and application strategy out of this public repository.

Only these bounded outputs may move into public sources:

- A supportable claim
- Its public or reference-check provenance class
- Its material caveat
- A named gap
- Public-safe location and availability language
- Target and company prompt context

## Interview rules

- Ask one concrete question per message and wait for the answer.
- Record the answer and its caveat before moving on.
- Use gradients when a binary answer would destroy useful information.
- Keep unknown, unclear, not yet verified, no, and zero distinct.
- Ask a follow-up only when it could change a public claim, named gap, target route, or interview recommendation.
- Treat Sam's correction as authority for his history, then identify what would make the claim publicly inspectable or reference-check strong.

## Sequence

### 1. Define the durable wedge

Decide whether the role belongs to an existing target family, reveals a target that should survive beyond one employer, or is company-only.

Completion criterion: one durable target owns the positioning wedge, or the role is explicitly company-only.

### 2. Find the artifact conflict

Compare the role with the default hero, rotating titles, status, public resume, system prompt, recruiter FAQ, evidence ledger, and stated gaps. Ask about the single most consequential apparent contradiction first.

Completion criterion: each public statement that could incorrectly reject or overstate the role is named with its owning source.

### 3. Resolve load-bearing requirements

Order requirements by their likelihood of deciding an interview gate. For each requirement, ask only as far as needed:

1. Has Sam done this directly?
2. What did the system or work do?
3. What authority did Sam personally hold?
4. What were the scale and duration?
5. What changed because of the work?
6. What public artifact or private reference supports it?
7. What boundary keeps the public statement honest?

Completion criterion: every load-bearing requirement is direct, transferable, missing, or not yet verified, with material authority, scale, outcome, provenance, and caveat recorded.

### 4. Separate chronologies

Keep adjacent but non-equivalent experience separate, including AI/ML-enabled system administration, LLM experimentation, production workflow use, public collaborative artifacts, and independently released products.

Completion criterion: no duration claim adds unlike categories or converts experimentation into production experience.

### 5. Test title, authority, and management legibility

Separate formal line management, project leadership, vendor management, partner orchestration, advisory coaching, and executive influence. Evaluate capability level, evidence legibility, and entry path independently.

### 6. Resolve identity and location routing

Choose the honest identity, email family, and public-safe location presentation for the role. Keep street addresses, ZIP codes, precise residential cities, and phone numbers in private application artifacts.

Completion criterion: the paper artifact and targeted public context do not contradict one another.

### 7. Run the human gate

After the evidence map and artifact exist, simulate:

1. A 30-second recruiter scan
2. A five-minute hiring-manager review
3. An evidence challenge against every claim that changed either decision
4. Cold routing compared with a legitimate warm introduction

Assign remaining failures to artifact extraction, evidence legibility, work fit, or access rather than collapsing them into one score.

## Evidence record

| Field | Allowed result |
|---|---|
| Relationship | Direct, transferable, missing, not yet verified |
| Authority | Owner, decision participant, contributor, advisor, observer |
| Scale | Exact, approximate, unknown |
| Duration | Dated, approximate, unknown |
| Outcome | Verified metric, qualitative result, no result, unknown |
| Provenance | Public source, private reference, self-report |
| Disclosure | Default public, targeted public, direct-question only, private |
| Caveat | The shortest boundary that prevents overclaiming |

## Stop rule

Stop when every load-bearing requirement has a classification, provenance route, and caveat, and no unanswered question could change the public claim set, targeted context, named gaps, or human-gate verdict.

More biography is not completion. Decision-relevant evidence is completion.
